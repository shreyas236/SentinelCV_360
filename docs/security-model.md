# Security model

Canonical JSON recursively sorts object keys, preserves array order, rejects non-finite values and hashes UTF-8 bytes with SHA-256. Provenance digests and audit records use detached Ed25519 signatures. Deterministic verification rereads artifacts; it does not trust cached UI hashes. Sensor and service credentials are custom root-signed attestations, explicitly not X.509 certificates.

Inference records bind sensor, input/model/config hashes, preprocessing source digest, build and direct-dependency SBOM, runtime profile, output, timestamp, nonce, sequence and previous manifest. Container, hardware and operating-system attestations are declared unavailable. Sequence allocation and manifest persistence use an atomic database batch with a compare-and-swap stream head. Acceptance persists a unique nonce and a unique sensor/sequence pair. Read-only verification does not consume a nonce, so checking the same record twice does not falsely classify it as replay.

Hard integrity failures enforce quarantine recommendations and block operational execution of a model that differs from the signed reference. Unresolved deterministic failures cannot receive an ACCEPT recommendation. Statistical warnings lead to review and carry explicit limitations. Final case disposition requires signed analyst and supervisor receipts with distinct identities.

Local authentication uses scrypt password hashes, HTTP-only SameSite cookies, one-hour sessions, persistent failed-login lockout and server-side fixed roles. The private analysis process rejects requests without its ephemeral internal token. Client-supplied role headers are ignored by FastAPI. The hosted profile adds fixed workspace password accounts behind private platform access.

Version 1.1 replaces hosted demo role simulation with stored account roles and administrator-provisioned users. Hosted passwords use salted PBKDF2 and hashed opaque sessions; local passwords use scrypt. Selecting a role at login cannot grant permissions. Private platform access remains a separate outer gate. Session cookies are HTTP-only/SameSite, CSRF origin checks and persistent lockout protect login, and client submissions are bound to a contributor identity.

The stack uses local Keycloak code/PKCE, state and nonce, strict RS256 issuer/audience/time/signature validation, exactly one SentinelCV realm role and an administrator-managed contributor attribute. OIDC state is consumed once; sessions expire no later than their signed access token. Logout deletes the app session and directs the browser through Keycloak end-session. OTP is required by the generated realm; interactive enrollment remains an acceptance check.

Native weights are loaded from a bounded read-only inventory and hashed on each execution. Uploaded PyTorch uses safe state dictionaries for known architectures; remote model code and external ONNX data are disabled. Python audit hooks/resource limits are a defense layer, not a complete native-code containment boundary. The container profile adds privilege and network restrictions; its combined runtime has not yet been validated here.

Fabric records are immutable, signed by the pinned service Ed25519 key and endorsed by both sample organizations. The Gateway reports success after committed status and readback; audit verification compares signed local prefix roots and matching ledger records. The first pinned key must be independently checked during initialization. Sample organization CAs and a compromised ledger administrator do not establish independent real-world custody.
